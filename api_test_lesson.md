# Часть 1. Что такое API и зачем оно нужно

## 1.1 Простое объяснение

API — это способ, с помощью которого приложение общается с сервером.

Пример:

- пользователь нажимает кнопку;
- фронт отправляет запрос;
- сервер обрабатывает данные;
- сервер возвращает ответ.

## 1.2 Что такое HTTP

HTTP — это протокол, по которому отправляются запросы и ответы.

Главные методы:

- `GET` — получить данные
- `POST` — отправить данные
- `PATCH` — частично обновить
- `PUT` — полностью обновить
- `DELETE` — удалить

## 1.3 Что такое endpoint

Endpoint — это адрес, куда мы отправляем запрос.

Пример:

- `/api/auth/login/`

## 1.4 Что приходит в ответ

Ответ обычно содержит:

- статус код;
- JSON;
- заголовки;
- cookies.

# Часть 2. Как понимать статус-коды

Нужно объяснить не просто “код 200 — ок”, а смысл.

## Основные коды

- `200` — всё ок
- `201` — ресурс создан
- `400` — плохой запрос
- `401` — не авторизован
- `403` — доступ запрещён
- `404` — не найдено
- `422` — ошибка валидации
- `500` — внутренняя ошибка сервера

## Как объяснить это на практике

Показываем:

- если отправили правильные данные → `200`/`201`
- если данные невалидны → `400`/`422`
- если не залогинились → `401`/`403`

# Часть 3. Что такое JSON

JSON — это формат ответа, который обычно приходит от API.

Пример:

```json
{
  "id": 1,
  "email": "test@example.com",
  "status": "active"
}
```

## Что важно объяснить

- JSON — это структура данных
- можно получать поля
- можно проверять, что поле существует и его значение верное

# Часть 4. Как устроен API-тест

API-тест обычно выглядит так:

1. Формируем запрос
2. Отправляем запрос
3. Получаем ответ
4. Проверяем статус
5. Проверяем тело

Пример:

```python
response = requests.get("https://example.com/api/users")
assert response.status_code == 200
assert response.json()["count"] > 0
```

# Часть 7. Первый тест

## Пример простого теста

```python
import httpx

def test_example():
    response = httpx.get("https://jsonplaceholder.typicode.com/posts/1")
    assert response.status_code == 200
```

## Что тут важно

- `httpx.get(...)` — отправка запроса
- `response.status_code` — статус
- `assert` — проверка

# Часть 8. Как проверять JSON

Пример:

```python
import httpx

def test_response_has_expected_fields():
    response = httpx.get("https://jsonplaceholder.typicode.com/posts/1")
    assert response.status_code == 200

    data = response.json()
    assert "id" in data
    assert "title" in data
```

## Что нужно объяснить

- `response.json()` превращает ответ в Python-словарь
- можно проверять значения

# Часть 9. Как писать хорошие assert

Плохой assert:

```python
assert response.status_code == 200
```

Это уже хорошо, но нужно думать глубже.

Хороший assert — это проверка именно бизнес-смысла.

Примеры:

```python
assert response.json()["email"] == "test@example.com"
assert response.json()["is_active"] is True
assert "error" not in response.json()
```

# Часть 10. Негативные сценарии

Очень важно показать, что API надо проверять не только на “успех”, но и на ошибки.

## Примеры

- неверный email
- пустой пароль
- невалидный токен
- попытка получить несуществующий объект

Пример:

```python
def test_login_invalid_password():
    response = httpx.post(
        "https://example.com/api/login/",
        json={"email": "user@example.com", "password": "wrong"}
    )

    assert response.status_code == 400
    assert "error" in response.json()
```

# Часть 11. Работа с авторизацией

Это один из самых важных блоков.

## Что объяснить

- как передавать токен
- как передавать cookies
- как делать запрос к защищённому endpoint

Пример:

```python
headers = {
    "Authorization": "Bearer TOKEN"
}

    "https://example.com/api/profile/",

```

# Часть 12. Как работать с `pytest`-фикстурами

Фикстуры нужны, чтобы не дублировать код.

Пример:

```python
import pytest
import httpx

@pytest.fixture
def client():
    return httpx.Client(base_url="https://example.com")
```

И дальше:

```python
def test_get_profile(client):
    response = client.get("/api/profile/")
    assert response.status_code == 200
```

## Что объяснить

- фикстура создаёт объект один раз;
- удобно использовать в нескольких тестах;
- помогает избежать копипасты.

# Часть 13. Как делать параметризованные тесты

Очень полезно показать, как запускать один тест на разные данные.

Пример:

```python
import pytest
import httpx

@pytest.mark.parametrize(
    "email,password,expected_status",
    [
        ("valid@example.com", "123456", 200),
        ("invalid", "123456", 400),
        ("valid@example.com", "", 400),
    ]
)
def test_login_cases(email, password, expected_status):
    response = httpx.post(
        "https://example.com/api/login/",
        json={"email": email, "password": password}
    )
    assert response.status_code == expected_status
```

# Часть 14. Как искать причину падения теста

Это ключевой навык.

## Алгоритм

1. Посмотреть, какой именно assert упал
2. Понять, что именно пришло в ответ
3. Сравнить с ожидаемым
4. Проверить:
   - endpoint;
   - method;
   - body;
   - headers;
   - auth

## Пример мысли

Если тест падает на `status_code == 200`, а ответ `401`:

- возможно, не передан токен;
- возможно, endpoint другой;
- возможно, у сервера другой режим работы.

# Часть 15. Как писать хороший API-тест

Хороший тест должен быть:

- понятным;
- коротким;
- точным;
- проверяющим бизнес-логику;
- не зависящим от лишних деталей.

## Хороший тест:

- проверяет конкретное поведение;
- не проверяет “всё подряд”;
- не зависит от случайностей.
